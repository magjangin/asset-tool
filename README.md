# asset-tool (Spine Part Splitter)

뮤즈대시 같은 Unity 게임에서 추출한 **Spine 텍스처(PNG)를 파츠별 PNG로 잘라내는** 데스크톱 도구입니다.
캐릭터와 노트(씬) 아틀라스를 모두 다루고, 폴더 하나를 통째로 일괄 처리할 수 있습니다.
Avalonia UI + SkiaSharp로 만들었습니다.

## 기능

### 아틀라스(.atlas)로 분리
- libgdx/Spine `.atlas` 텍스트 형식을 읽습니다. `.atlas.txt`도 지원합니다(AssetStudio 추출본).
  - 구형: `xy` / `size` / `orig` / `offset` / `index`
  - 신형: `bounds` / `offsets`
  - 줄 구분은 libgdx 방식을 따릅니다. `:`가 있으면 속성, 없으면 리전 이름입니다. 그래서 사용자 정의 필드가 있어도 가짜 리전이 생기지 않습니다.
- 회전된 리전(`rotate: true` / `90` / `180` / `270`)을 픽셀 단위로 정확히 되돌립니다.
- 아틀라스를 열면 페이지 PNG를 근처 폴더에서 찾아 자동으로 엽니다. `TextAsset\`과 `Texture2D\`처럼 폴더가 갈라져 있어도 찾습니다.
- **겹친 리전에 끼어든 옆 파츠 제거(기본값)** — 아래 [정리 방식](#정리-방식) 참고.
- **잘린 여백 복원(선택)**: `orig`/`offset`을 써서 패킹 때 잘린 투명 여백을 되살려 원본 크기로 저장합니다. Spine에서 다시 패킹할 때 유용합니다.
- **색 기반 누끼(구버전, 선택)**: 아틀라스와 PNG가 서로 맞지 않을 때만 쓰는 보조 기능입니다. 정상 아틀라스에서는 파츠 일부를 지울 수 있어서 기본으로 꺼져 있습니다.

### 폴더 일괄 처리
- 고른 폴더 아래의 모든 `.atlas` / `.atlas.txt`를 찾아 페이지 PNG를 자동으로 짝지어 분리합니다.
  - 아틀라스 폴더를 먼저 보고, 없으면 경로가 가장 비슷한 PNG를 고릅니다.
  - 예: `TextAsset\1_rampage\skin1`은 `Texture2D\1_rampage\skin1`과 짝지어집니다.
- 여러 페이지 아틀라스도 한 번에 처리합니다.
- 결과 위치: `출력\<입력 기준 아틀라스 폴더>\<아틀라스 이름>\<리전>.png`
  - 폴더 위치를 그대로 따라가므로, 이름이 같은 아틀라스(스킨1/스킨2)도 섞이지 않습니다.
- 아틀라스에 쓰이지 않은 PNG(예: 뮤즈대시 `0102_*` 롱노트 텍스처)는 그대로 복사합니다(선택).
- 진행률, 취소, 로그 화면과 로그 파일(`_split_log.txt`)을 지원합니다.
- 기본 스킨 외의 스킨을 가진 `.skel`(Spine 3.8)을 찾아 로그에 경고합니다. 몸통 같은 부위가 스킨에만 들어 있으면 Spine에서 스킨을 고르기 전까지 비어 보입니다. MCP 결과에는 `skinSkeletons`/`skinNotice`로 나옵니다.
- 한 아틀라스에서 오류가 나도 기록만 하고 다음 아틀라스로 넘어갑니다.
- 출력 폴더가 입력 폴더 안에 있어도 출력물을 다시 처리하지 않습니다. 입력과 출력이 같은 폴더면 시작하지 않습니다.

- **폴더 펼치기(선택)**: 아틀라스의 원래 폴더를 빼고 `출력\<아틀라스 이름>\<리전>.png`로 저장합니다. Spine 이미지 폴더 가져오기가 읽는 `TextAsset` 같은 구조입니다. 이름이 같은 아틀라스는 `_2`, `_3`을 붙이고, 아틀라스에 안 쓰인 PNG는 `_unused_pngs\`로 모읍니다. MCP `extract_and_split`은 기본으로 이 구조를 씁니다.
- **같은 이름의 텍스처가 둘 이상일 때**: AssetStudio는 이름이 겹치는 텍스처를 `이름_#번호.png`로 둘 다 저장하는데, 서로 다른 그림일 수 있고(예: 흰 실루엣과 분홍 빛 버전) 어느 쪽이 아틀라스의 짝인지는 파일만으로 알 수 없습니다. 어느 쪽이 원래 이름을 받는지도 추출할 때마다 달라서, 예전에는 결과가 실행마다 바뀌었습니다. 지금은 내용 해시 순서로 정렬해 **모두 분리**합니다: 첫 번째는 `이름\`, 나머지는 `이름_v2\`, `이름_v3\`에 저장하고 로그에 알립니다. 이름만 같고 크기가 아틀라스와 다른 텍스처는 다른 그림이므로 제외합니다. 뮤즈대시 번들 29개에서 둘 다 저장되는 아틀라스는 19개입니다.

### PNG 자동 감지로 분리
- 투명하지 않은 픽셀(알파 10 이상)끼리 8방향으로 이어진 덩어리를 하나의 파츠로 잘라냅니다.
- 4픽셀 미만의 작은 점은 무시합니다.

### 내보내기
- 체크한 파츠만 PNG로 저장합니다. 목록에서 이름을 바로 고칠 수 있습니다.
- 파일 이름 방식(일괄 처리에도 적용):
  - 폴더 구조 유지: `0103/images_air/fx` → `0103\images_air\fx.png` (기본값, Spine 재패킹용)
  - 폴더를 `_`로 연결: `0103_images_air_fx.png`
  - 마지막 이름만: `fx.png`
- 이름이 겹치면 `_2`, `_3`을 붙입니다. 쓸 수 없는 문자, `..`, 예약어(`CON` 등)도 정리합니다.
- 기존 파일을 덮어쓰면 몇 개를 덮어썼는지 상태줄에 알려 줍니다.

### 기타
- PNG를 straight-alpha 그대로 읽고 써서, 거의 투명한 픽셀의 색까지 손실 없이 보존합니다.
- 미리보기와 썸네일에 체크무늬 배경을 깔아서 흰 fx 선과 어두운 그림자가 모두 보입니다.
- 무거운 작업은 백그라운드에서 돌아서 화면이 멈추지 않습니다. 오류는 프로그램을 끄지 않고 상태줄에 표시합니다.

## 정리 방식

Spine의 **폴리곤 패킹**으로 만든 아틀라스(뮤즈대시 캐릭터 아틀라스)는 리전 사각형끼리 겹칩니다.
그래서 사각형대로 자르면 옆 파츠 조각이 섞여 들어옵니다.
노트/씬 아틀라스는 대부분 겹치지 않습니다.

`AtlasOverlapResolver`는 색을 보지 않고 **아틀라스 좌표만으로** 각 픽셀의 주인 리전을 정합니다.

1. 사각형 하나에만 속한 불투명 픽셀은 그 리전 것입니다. 여기서 시작해, 맞닿은 불투명 픽셀로 자기 사각형 안에서만 넓혀 갑니다.
2. 아무 데서도 닿지 않은 덩어리(큰 머리카락 사각형 안에 통째로 들어간 작은 파츠 등)는, 그 덩어리를 다 담는 가장 작은 사각형의 리전에 줍니다.
3. 반투명 가장자리 픽셀은 맞닿은 불투명 픽셀의 주인을 따릅니다. 이웃 파츠끼리는 알파 32 미만의 희미한 AA 픽셀 몇 개로 이어지는 경우가 있어서, 소유권은 불투명 픽셀로 먼저 정합니다.

리전이 겹치지 않는 아틀라스는 아무것도 건드리지 않습니다.
뮤즈대시 노트·캐릭터 아틀라스 484개 리전으로 확인한 결과입니다.
- 447개는 원본 크롭과 픽셀 단위로 같습니다.
- 나머지는 끼어든 옆 파츠 조각만 빠집니다.
- 통째로 사라지는 리전은 없습니다. 정리하면 리전이 완전히 비게 될 때는 정리하지 않은 원본을 쓰고 로그에 남깁니다(옆 파츠 조각이 약간 묻을 수 있음).

예전 색 기반 누끼는 모서리가 투명하면 "검정 배경"으로 착각했습니다. 그래서 노트의 `shadow`(어두운 타원) 같은 파츠를 통째로 지웠습니다. 지금은 불투명한 모서리만 기준색으로 쓰도록 고쳤지만, 기본으로는 꺼 두었습니다.

## AI에서 호출하기 (MCP 서버)

같은 로직을 [MCP](https://modelcontextprotocol.io) 서버(`AssetTool.Mcp`)로도 쓸 수 있어서 Claude 같은 AI가 도구로 직접 호출합니다.
stdio로 동작하며, 저장소 루트의 `.mcp.json`에 등록되어 있습니다. 실행 스크립트(`scripts/run-mcp.cmd`)가 서버를 띄울 때마다 먼저 빌드하므로, 코드를 바꾼 뒤에는 Claude Code를 재시작하기만 하면 최신 코드가 적용됩니다.

| 도구 | 하는 일 |
| --- | --- |
| `list_atlas_regions` | `.atlas`를 읽어 페이지·리전 목록을 보여 줍니다(아무것도 쓰지 않음). |
| `split_atlas_folder` | 폴더 안의 모든 아틀라스를 파츠 PNG로 분리합니다(폴더 일괄 처리와 같음). |
| `split_png_by_alpha` | 아틀라스가 없는 PNG 한 장을 알파 덩어리로 분리합니다. |
| `extract_unity_bundles` | Unity 번들에서 Texture2D·TextAsset을 AssetStudioMod CLI로 추출합니다(번들별 하위 폴더). |
| `extract_and_split` | 번들 추출부터 파츠 분리까지 한 번에 처리합니다. 번들마다 `파츠\`(아틀라스 이름별 파츠), `스프라이트\`(아틀라스 없는 낱개 이미지: 롱노트·콜라보 스킨 노트·히트 포인트·배경 등), `원본\`(`.atlas`, `.skel`, 페이지 PNG) 폴더를 만듭니다. |
| `repack_parts` | 파츠 PNG 폴더를 다시 Spine/libgdx 아틀라스(`.atlas` + 페이지 PNG)로 묶습니다. |
| `spine_contact_sheet` | `.skel`의 모든 애니메이션을 Spine 에디터 CLI로 렌더해 컨택트 시트(애니메이션별 한 줄, 프레임마다 시간 표시)로 만듭니다. |
| `spine_render_batch` | 여러 장면의 스켈레톤을 한 번에 렌더합니다(기본: 노트 05~08·10~17의 `_air`/`_road`, `standby` 첫 프레임). 투명 배경으로 내용물만 잘라 `<출력>\<장면>\<스켈레톤>.png`로 저장합니다. 공중에 뜬 몬스터는 그림자가 수백 px 아래에 떨어져 있어서, 멀리 떨어진 납작한 그림자 덩어리는 크롭에서 뺍니다(몬스터 바로 아래 그림자는 유지). |
| `spine_render_frames` | 시트에서 고른 프레임(`standby@0.50=cover`)을 최종 PNG로 렌더하고 `recipe.json`로 저장합니다. 레시피로 다시 렌더할 수도 있습니다. |

번들 추출은 [AssetStudioMod](https://github.com/aelurum/AssetStudio) CLI를 호출합니다. `AssetStudioModCLI.exe` 경로를
환경변수 `ASSETSTUDIO_CLI`(`.mcp.json`의 `env`)나 도구의 `cliPath`로 알려 주세요.

### 리패킹 (`repack_parts`)

파츠를 고친 뒤 Spine/libgdx 런타임에서 다시 쓰려면 아틀라스가 필요합니다. 외부 프로그램 없이 직접 패킹합니다(MaxRects, 회전 없음).

- 리전 이름은 파츠 폴더 기준 상대 경로입니다. `keep_folders`로 분리한 폴더를 넣으면 원래 이름(`0103/images_air/fx`)으로 돌아갑니다.
- 투명 여백은 잘라내고 `orig`/`offset`으로 기록합니다(Spine 패커와 같은 방식). 분리 때 "잘린 여백 복원"을 켜면 원본 크기로 돌아옵니다.
- 페이지는 기본 2048까지, 2의 거듭제곱 크기로 만들며 넘치면 `이름2.png`로 이어집니다. 파츠 사이 여백은 기본 2px입니다.
- 검증: 뮤즈대시 아틀라스 125개(파츠 4681개)를 분리 → 리패킹 → 다시 분리해 비교했더니 보이는 픽셀이 100% 같았습니다.
- 한계: 회전·폴리곤 패킹을 쓰지 않아서 원본 아틀라스보다 페이지가 커질 수 있습니다(`powerOfTwo=false`로 줄일 수 있음). 스켈레톤(`.skel`)은 건드리지 않습니다.

### 보스·노트를 통짜 이미지로 (`spine_contact_sheet` → `spine_render_frames`)

Spine 에디터에서 skel을 열고, 파츠 경로를 잡고, 애니메이션 탭에서 마커를 움직여 프레임을 찍던 작업을 CLI로 대신합니다. **라이선스가 있는 Spine 에디터(Pro, 3.8.x)** 가 필요하고, 기본 경로가 아니면 환경변수 `SPINE_CLI`나 `spineCliPath`로 `Spine.com`을 알려 주세요.

1. `spine_contact_sheet`로 `outputDir\sheets\sheet_NN.png`를 만듭니다. 한 줄이 애니메이션 하나이고, 각 프레임에 `시간 #번호`가 적혀 있습니다. 캔버스는 애니메이션이 실제로 그리는 영역으로 잘라 보여 줍니다. 모든 프레임은 `frames\`에도 남습니다.
2. 시트를 보고 프레임을 골라 `spine_render_frames`에 `frames: ["standby@0.50=cover", ...]`(애니메이션@초=파일 이름)로 넘깁니다. 결과는 `picked\<이름>.png`, 선택은 `recipe.json`에 저장됩니다.
3. 같은 선택을 다른 크기로 다시 뽑으려면 `recipePath`와 `exportScalePercent`를 주면 됩니다.

- **임포트 스케일 0.5(기본값, 바꿀 수 있음)**: 뮤즈대시 파츠 PNG는 스켈레톤이 만들어진 크기의 절반이라, 1배로 가져오면 조각들이 흩어져 보입니다. 0.5로 가져와야 에디터에서 보던 조립된 모양이 나옵니다(보스 `0101`의 `standby`는 307×430).
- 파츠 경로는 `<번들>\원본\X.skel` 옆의 `<번들>\파츠\X`를 자동으로 씁니다. 다르면 `partsDir`를 주세요. skel 머리말에는 이미지 경로가 없고 CLI로도 지정할 수 없어서, 내부적으로 skel → 프로젝트 → JSON으로 한 번 바꿔 `images` 경로를 채운 뒤 다시 가져옵니다. 이 프로젝트는 `outputDir\_spine\`에 저장되어 같은 입력이면 재사용합니다(첫 실행 약 1분, 이후 20~30초).
- **공용 아틀라스**: 장면 몬스터(`0105_air` 등)는 자기 아틀라스가 없고 `파츠\s01_atlas\0105\...`처럼 장면 공용 폴더에 들어 있습니다. 파츠 경로 자동 탐색이 이 폴더를 먼저 고릅니다.
- **일괄 렌더(`spine_render_batch`)**: 같은 파츠 폴더를 쓰는 스켈레톤을 한 프로젝트로 묶어서, 장면 하나를 약 2분에 처리합니다(스켈레톤마다 1분씩 걸리던 것을 줄임). `scenes: "1-10,12"`, `skeletonPattern`(정규식), `animation`, `time`으로 고릅니다. 해당 애니메이션이 없는 스켈레톤(예: 보스 등장용 `0107`, `0115`)은 `missingAnimation`에 나옵니다. 몬스터 색은 `_air`가 파랑, `_road`가 분홍으로 나뉩니다(0113 기준).
- 같은 애니메이션의 프레임은 같은 캔버스 크기(최대 영역)로 나옵니다. 에디터에서 내보낼 때와 같습니다.
- 파츠가 모자라면 `warnings`에 "not found"가 나옵니다(예: `0103_air`는 `0103/images_road/smoke`를 쓰는데 이 아틀라스에는 없음).

## 빌드 / 실행

필요: [.NET 10 SDK](https://dotnet.microsoft.com/download)

```bash
dotnet run --project "asset tool/asset tool.csproj"
```

Visual Studio에서는 `asset tool.slnx`를 열면 됩니다.

## 알려진 한계

- 단일 파일 모드는 열린 PNG에 맞는 페이지 하나만 분리합니다. 여러 페이지는 폴더 일괄 처리를 쓰세요.
- 겹치는 영역 안에만 있는 작은 덩어리는 "가장 작은 사각형"에 배정되므로, 드물게 주인이 틀릴 수 있습니다.
- 색 기반 "작은 덩어리 제거"는 동공·하이라이트처럼 색이 확 다른 안쪽 디테일도 지울 수 있습니다.
